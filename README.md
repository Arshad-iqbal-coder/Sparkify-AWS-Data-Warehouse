# Sparkify AWS Data Warehouse – S3 to Redshift ETL

## Project Overview

Sparkify is a music streaming startup that wants to analyze user activity and understand which songs users are listening to.

The company stores two types of data in Amazon S3:

- Song metadata
- User activity logs

The objective of this project is to build an ETL pipeline that:

1. Extracts JSON data from Amazon S3.
2. Loads the raw data into staging tables in Amazon Redshift.
3. Transforms the staging data using SQL.
4. Loads the transformed data into a star-schema data warehouse.
5. Provides a structure optimized for analytical queries.

The final data warehouse allows Sparkify's analytics team to analyze:

- Most played songs
- User activity
- Peak listening hours
- User subscription levels
- Artist popularity

## Staging Tables

The raw data is first loaded into two staging tables before being transformed into the final warehouse.

### `staging_events`

Stores raw user activity log data loaded from the Sparkify log dataset.

### `staging_songs`

Stores raw song and artist metadata loaded from the Sparkify song dataset.

The staging layer provides separation between the raw source data and the final analytical warehouse.

---

## Why Star Schema?

A star schema was selected because the primary purpose of the database is analytical querying.

The design separates:

- **Events that can be measured** → Fact table
- **Information used to describe those events** → Dimension tables

### Benefits

- Simple analytical queries
- Easier joins
- Efficient aggregations
- Clear separation between facts and dimensions
- Suitable for business intelligence and reporting workloads

For example, analysts can join `songplays` with `users`, `songs`, `artists`, and `time` to answer business questions about listening behavior.

## ETL Pipeline

The ETL pipeline consists of three major stages.

### 1. Extract and Load

Raw JSON data is stored in Amazon S3.

The pipeline uses Redshift's `COPY` command to load the data directly from S3 into the staging tables.

```text
Amazon S3
   |
   | COPY
   v
Redshift Staging Tables
```

The `staging_events` table loads the log data, while `staging_songs` loads the song metadata.

---

### 2. Transform

SQL `INSERT ... SELECT` statements are used to transform the staging data.

The transformations:

- Select required columns
- Filter relevant records
- Extract song-play events
- Connect song and artist information
- Generate time attributes
- Prepare data for analytical queries

---

### 3. Load

The transformed data is inserted into the final star-schema tables:

```text
             staging_events
                   |
                   |
             +-----+------+
             |            |
             v            v
          users       songplays
                          |
                          |
             +------------+------------+
             |            |            |
             v            v            v
           songs       artists        time
```

## Project Files

### `create_tables.py`

Responsible for creating the database tables in Amazon Redshift.

The script:

- Connects to the Redshift database
- Drops existing tables
- Creates staging tables
- Creates fact and dimension tables

It allows the database to be reset and recreated during development and testing.

---

### `etl.py`

Contains the main ETL pipeline.

The script:

- Connects to Amazon Redshift
- Loads song data from Amazon S3
- Loads log data from Amazon S3
- Populates staging tables using Redshift `COPY`
- Transforms staging data
- Inserts data into the fact and dimension tables

---

### `sql_queries.py`

Contains the SQL statements used by the project.

The file includes:

- `DROP TABLE` statements
- `CREATE TABLE` statements
- Staging table definitions
- `COPY` statements
- `INSERT` statements
- Fact and dimension table transformations

Keeping SQL queries in a separate file makes the Python ETL code more modular and easier to maintain.

## How to Run the Project

### Prerequisites

Before running the project, make sure you have:

- Python installed
- Required Python packages installed
- An AWS account
- An Amazon Redshift cluster
- An IAM role with permission to access the required S3 data
- Access to the Sparkify datasets in Amazon S3

---

### 1. Configure Redshift

Create an Amazon Redshift cluster and obtain the database connection details.

Configure the required values in your local `dwh.cfg` file.

Example:

```ini
[CLUSTER]
HOST=<your-redshift-endpoint>
DB_NAME=dev
DB_USER=<your-username>
DB_PASSWORD=<your-password>
DB_PORT=5439

[IAM_ROLE]
ARN=<your-iam-role-arn>
```

Do not upload your real credentials to GitHub.

---

### 2. Create Database Tables

Run:

```bash
python create_tables.py
```

This will:

1. Connect to Redshift.
2. Drop existing tables if they exist.
3. Create the staging tables.
4. Create the fact table.
5. Create the dimension tables.

---

### 3. Run the ETL Pipeline

After successfully creating the tables, run:

```bash
python etl.py
```

The ETL script will:

1. Load log data from S3 into `staging_events`.
2. Load song data from S3 into `staging_songs`.
3. Transform the staging data.
4. Populate the `songplays` fact table.
5. Populate the `users`, `songs`, `artists`, and `time` dimension tables.
